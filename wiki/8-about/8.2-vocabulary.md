# 8.2 Vocabulary

> **Status:** Reference — definitions, not a claim about any code.

Words this book uses precisely. Each pair looks like a synonym and isn't, and
each distinction exists because collapsing it would let a page overstate.

## ok vs verified

**`ok`** means an operation completed without throwing. **Verified** means
somebody checked the outcome and it was right.

`GET /health` returns `{"ok": true, "providers": [...eighteen names...]}`. That
means the process is running and `providers.yaml` parsed. It does not mean any
API key is valid, any browser session is alive, or any of the eighteen would
answer a request. Not one of them is contacted.

The same gap runs through the browser driver. `wspr login` writes its
`.logged-in` sentinel when you press Enter — not when a login is confirmed
([§5.3](../5-browser-providers/5.3-sessions-and-login.md#the-login-flow)).
Warming prints `✓ <name> ready` after a navigation whose failure it swallowed
([§6.2](../6-operating/6.2-startup-and-environment.md#what-warming-actually-does)).
Both are `ok`. Neither is verified.

A green checkmark that only means "no exception was thrown" is worth saying out
loud every time it appears.

## live-verified vs recon'd

**Live-verified** — a real request went to the real site and a real answer came
back. Evidence is a commit, a run, or a fixed selector somebody watched fail
first.

**Recon'd** — selectors were read off the live DOM by a human with devtools
open. Accurate about what is on the page. Says nothing about whether the driver
works, because the piece that cannot be recon'd is `responseSelector`: knowing
which container will hold an answer requires generating one.

Two providers are live-verified; four are recon'd; four are neither
([§5.5](../5-browser-providers/5.5-what-is-verified.md)). All four recon'd
entries name `responseSelector` as the unverified field, which is not a
coincidence — it is the only one you cannot check without sending a message.

The rule for this book: **a provider with eighteen configured fields and one
unverified selector is described as unverified, every time.**

## declared vs works

`providers.yaml` can declare anything. Declaration is free; a model name costs
one line and no browser.

Twenty-six model names are declared across the ten browser providers. Two carry
a selector. Zero have demonstrably switched a model
([§5.6](../5-browser-providers/5.6-model-switching.md#what-is-configured)).

This is why the one optional capability in the code — embeddings — is expressed
as a **type guard** rather than a config flag
([§2.3](../2-architecture/2.3-the-provider-contract.md#capabilities-are-structural-not-declared)).
`typeof p.embed === "function"` cannot be aspirational. There is no gap between
declared and works because there is no declaration.

Where a book table lists capabilities, it must say which kind it is listing.

## implemented vs configured

A mechanism that runs is not a feature that does something.

`switchModel` is complete, correct, and reachable from all four routes. On nine
of ten browser providers it returns on its first line, because the config it
reads is an empty string. The code is implemented; the feature is not
configured; a caller sees neither — the request succeeds and the response echoes
a model that was never selected.

The register carries both facts as separate rows for exactly this reason
([§7](../7-status.md)).

## Door A vs Door B

Shorthand used throughout, defined in
[§1.2](../1-idea/1.2-two-doors.md):

- **Door A** — API-key providers. `ApiLLMProvider`, HTTPS to an
  OpenAI-compatible endpoint. 8 providers.
- **Door B** — browser providers. `WebLLMProvider`, Playwright driving a real
  chat website. 10 providers.

They are deliberately indistinguishable to a caller, which is the design's
achievement and the source of its sharpest edge: `newChat` and conversation
state mean genuinely different things per door
([§3.2](../3-api/3.2-choosing-a-model.md#conversation-state-is-not-symmetric)).

## provider vs model

**Provider** — a key in `providers.yaml`. There are eighteen, and they are what
`GET /v1/models` lists.

**Model** — what runs behind a provider. The server does not enumerate these,
does not validate them, and mostly does not know they exist. `"model": "groq"`
names a provider; `"model": "groq/llama-3.1-8b-instant"` names both
([§3.2](../3-api/3.2-choosing-a-model.md)).

When this book writes "eighteen providers" it means eighteen, and it never
means eighteen models.

## working tree vs published

Some of what this book describes is not in `llm-whisperer@0.1.5`. Where that is
true the page's banner and the register row both say **working tree**, and
[§7](../7-status.md) lists the uncommitted files.

"Shipped" is not used as a status word anywhere. It reads as a synonym for
Implemented and sorts nowhere against Partial or Planned — which is precisely
the failure mode the closed marker vocabulary exists to prevent
([§8.1](./8.1-how-this-book-is-written.md#1-every-page-says-what-it-is)).
