# 1.3 Terms of service, honestly

> **Status:** Reference — this page is about obligations and risk, not about
> the state of any code.

Door B ([§1.2](./1.2-two-doors.md)) automates web interfaces that were built for
people. Most of the providers it drives explicitly prohibit that.

This page exists because the alternative — a cheerful feature list that never
mentions it — would be the book overstating itself, which is the one thing
[§8.1](../8-about/8.1-how-this-book-is-written.md) forbids.

## What the ten browser providers say

| Provider | Position |
|---|---|
| OpenAI / ChatGPT | [Terms of Use](https://openai.com/policies/terms-of-use/) — prohibits scraping and automated access |
| Anthropic / Claude | [Usage Policy](https://www.anthropic.com/legal/aup) — prohibits automated web UI access |
| xAI / Grok | [Terms of Service](https://x.ai/legal/terms-of-service) — prohibits automated access |
| Alibaba / Qwen | Prohibits bots and automated access |
| DeepSeek | Prohibits automated access |
| Zhipu / GLM | Prohibits automated access |
| Moonshot / Kimi | Prohibits automated access |
| MiniMax | Prohibits automated access |
| Inflection / Pi | Prohibits automated access |
| Baidu / ERNIE | Prohibits automated access |

That is **ten out of ten**. There is no browser provider in this project whose
terms invite what the project does to it.

## What that means in practice

- **Your account is the thing at risk.** The browser door works by logging in as
  you and reusing your session ([§5.3](../5-browser-providers/5.3-sessions-and-login.md)).
  If a provider decides an account is automating its web UI, the account it acts
  against is yours.
- **Rate limits and challenges are the normal outcome**, not the exceptional
  one. Cloudflare interstitials on `chatgpt.com` are common enough that
  `providers.yaml` carries a comment about them.
- **Nothing here is an exploit.** There is no captcha solving, no login
  bypass, no paywall circumvention. The tool types into the box you would have
  typed into. The line it crosses is *automation*, not *access*.
- **Autonomous login goes a step further, and is a materially stronger claim.**
  Historically you logged in by hand and the tool never saw a password
  ([§5.3](../5-browser-providers/5.3-sessions-and-login.md)). With the
  credential vault, the tool now *submits* stored credentials on your behalf
  when a session lapses. It does not defeat captchas — an interlocked form is
  simply not recovered and it falls back to the manual flow — but it is
  distinctly closer to "the account is the thing at risk" than typing into an
  already-open session was. The store of passwords is you handing the tool your
  keys, encrypted at rest, and only ever re-sent to the site you gave them for.

## What the project does about it

Three things, all of them disclosure rather than mitigation:

1. The README, [`docs/overview.md`](../../docs/overview.md) — which opens with
   the same table — and this page all state it plainly, and the README puts a ⚠ directly under
   the browser provider table rather than in a footer.
2. Door A is presented first and recommended everywhere. The npm description
   and the social copy in `todo` both lead with the API-key story; the author's
   own note there reads *"that part is ToS-gray, so it's safer not to headline
   'scrape ChatGPT for free' publicly."*
3. `puppeteer-extra-plugin-stealth` is loaded in `src/browser.ts:8`, along with
   `--disable-blink-features=AutomationControlled` and a pinned desktop user
   agent.

Point 3 deserves naming for what it is: **it reduces bot detection.** It is
there so that a real browser driving a real logged-in session isn't refused for
looking automated — but "makes automation harder to detect" is an accurate
description of it, and a book that called it merely "compatibility" would be
lying by word choice.

## The honest summary

> Use the browser door for personal experimentation, research, or local
> prototyping only, at your own risk. For anything production, pay for the
> official API — which is Door A, which is already built.

Publishing this on npm does not imply that any provider endorses it, and using
it does not transfer the risk to anyone but you.
