# 6.1 Install and first run

> **Status:** Implemented — every command here works against 0.1.5.
> [`docs/quickstart.md`](../../docs/quickstart.md) is the step-by-step version;
> this page is the shape of the thing plus the parts that bite.

```bash
npm install -g llm-whisperer
```

That is enough for all eight API-key providers. Browser providers need a
browser, which is a separate download and, on Linux, separate system libraries.

## Door A, in about a minute

```bash
echo "GROQ_API_KEY=your-key-here" >> .env    # free, no card: console.groq.com/keys
wspr serve
```

```bash
curl http://localhost:9777/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"groq","messages":[{"role":"user","content":"Hello!"}]}'
```

The `.env` file is read from **the directory you run `wspr` in**, not from where
the package is installed — `import "dotenv/config"` at `src/cli.ts:2`. Running
`wspr serve` from your home directory when the keys are in a project folder is
the most common "why does it say my key is missing" cause.

Missing keys are a warning, not a failure. The server starts, lists what is
missing, and those providers fail at request time
([§4.2](../4-api-key-providers/4.2-the-shipped-roster.md#what-startup-tells-you)).

## Door B, from nothing

```bash
npx playwright install chromium          # ~170 MB, one time
```

On Linux and WSL that is not sufficient — Chromium needs system libraries that
Playwright does not bundle:

```bash
sudo npx playwright install-deps chromium
```

The symptom when they are missing is a launch failure naming a shared object,
usually `libnspr4.so`. On Ubuntu 24.04 / WSL the manual equivalent is:

```bash
sudo apt update
sudo apt install -y libnspr4 libnss3 libatk-bridge2.0-0 libgtk-3-0 libxss1 libasound2t64
```

Then the honest first test, because it needs no login and is one of the two
live-verified providers ([§5.5](../5-browser-providers/5.5-what-is-verified.md)):

```bash
wspr serve
curl -s -X POST http://localhost:9777/chat \
  -H "Content-Type: application/json" \
  -d '{"provider":"pi","messages":[{"role":"user","content":"Hello!"}]}' | jq -r .message.content
```

`HEADLESS` defaults to `false`, so a browser window will open and you will watch
it type. Keep it that way at first — it is the only view you get into what the
driver is doing.

### Logging in to a provider

```bash
# stop `wspr serve` first — Chrome locks the profile to one process
wspr login qwen
```

A window opens at the provider. Log in, get to the chat screen, press Enter in
the terminal. Then restart `wspr serve`.

Two things worth knowing before you try:

- **The server must be stopped.** This is not advice, it is a hard lock, and the
  reason is [§5.3](../5-browser-providers/5.3-sessions-and-login.md#the-lock).
- **If the login is Google OAuth — which Qwen's is — you need
  `WSPR_BROWSER_CHANNEL=chrome`.** Google refuses to sign in through
  Playwright's bundled Chromium with *"this browser may not be secure"*. Set
  `WSPR_BROWSER_CHANNEL=chrome` in `.env` (it must be installed locally) for
  both the login and the serve.

## Running from source

```bash
git clone https://github.com/Aananda-giri/llm-whisperer
cd llm-whisperer
pnpm install
pnpm exec playwright install chromium
pnpm run serve       # tsx, no build step
```

| Script | Does |
|---|---|
| `pnpm run serve` | Run `src/cli.ts serve` through `tsx` |
| `pnpm run dev` | Same, with file-watching |
| `pnpm run login` | `src/cli.ts login` — append the provider name |
| `pnpm run build` | `tsc` → `dist/` |
| `pnpm run start` | Run the compiled `dist/cli.js` |
| `pnpm run chrome` | Launch Chrome with `--remote-debugging-port=9222` for CDP mode |

`pnpm` rather than `npm` is deliberate and explained in
[§6.4](./6.4-pnpm-and-publishing.md).

## Port 9777

The default, chosen because 9777 spells **WSPR** on a phone keypad and avoids
the crowded 3000/5000/8000 range. It moved there from 3000 in commit `82cde32`.
Override with `PORT`.

The server binds **all interfaces**, not just loopback. On an untrusted network
that matters — see
[§3.4](../3-api/3.4-embeddings-and-auth.md#what-this-is-and-is-not).

## The one-minute sanity check

```bash
curl -s localhost:9777/health | jq
```

Eighteen provider names and `ok: true` means the process is up and
`providers.yaml` parsed. It does **not** mean any of them work — not one key is
validated and not one session is checked
([§8.2](../8-about/8.2-vocabulary.md#ok-vs-verified)).
