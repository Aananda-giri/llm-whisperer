# 4.1 One class, many services

> **Status:** Implemented — `src/providers/api.ts`, 151 lines, all shipped.

Eight providers. One class. No subclasses, no per-provider branches, no `if
(name === "cloudflare")` anywhere in the file.

That is possible because all eight speak the same protocol. OpenAI's
`/chat/completions` request shape won, and Google, Groq, Cerebras, Mistral,
Cloudflare, OpenRouter and DigitalOcean all ship a compatibility layer for it.
Adding a provider is therefore not an integration — it is three lines of YAML
naming a URL, a default model, and an environment variable
([§2.2](../2-architecture/2.2-configuration-is-the-product.md)).

## The whole request

```ts
const key = process.env[this.api.keyEnv];
if (!key) throw new ApiKeyMissingError(this.name, this.api.keyEnv);

const baseUrl  = this.resolveEnv(this.api.baseUrl).replace(/\/+$/, "");
const endpoint = `${baseUrl}/chat/completions`;
const model    = options.model ?? this.api.model;

const res = await fetch(endpoint, {
  method: "POST",
  headers: { "Content-Type": "application/json", Authorization: `Bearer ${key}` },
  body: JSON.stringify({ model, messages, stream: true }),
});
```

Notable for what it doesn't do:

- **No dependency.** `fetch` is Node's global (hence `engines: node >= 18`).
  There is no `openai` package in `dependencies` — llm-whisperer speaks the
  OpenAI protocol without importing anything that knows about it.
- **No parameter passthrough.** `temperature`, `top_p`, `max_tokens`,
  `stop`, `tools`, `response_format`, `seed` — all silently dropped. Only
  `model` and `messages` are forwarded. A caller that sets
  `temperature: 0` gets whatever the upstream default is, with no indication
  the setting was ignored. This is the single largest gap in Door A's
  OpenAI compatibility, and it is filed in [§7](../7-status.md).
- **No retry, no timeout.** A hung upstream hangs the request until the
  client gives up. Node's `fetch` has no default timeout.
- **`stream: true` always** — see
  [§3.3](../3-api/3.3-streaming.md#in-door-a-parsing-the-upstream-stream).

The trailing-slash strip (`.replace(/\/+$/, "")`) is there so a `baseUrl`
written as `https://api.groq.com/openai/v1/` doesn't produce a double slash.
Small, and the kind of thing that costs an afternoon when it's missing.

## The Cloudflare problem

Seven of the eight providers authenticate with a bearer token and nothing else.
Cloudflare needs your **account id in the URL path**:

```
https://api.cloudflare.com/client/v4/accounts/<ACCOUNT_ID>/ai/v1
```

That is not a secret, but it is per-user, so it cannot be hard-coded in a YAML
file shipped to every npm user. The solution is a placeholder resolved from the
environment at request time:

```yaml
  cloudflare:
    api:
      baseUrl: "https://api.cloudflare.com/client/v4/accounts/${CLOUDFLARE_ACCOUNT_ID}/ai/v1"
      model: "@cf/meta/llama-3.3-70b-instruct-fp8-fast"
      keyEnv: "CLOUDFLARE_API_TOKEN"
```

```ts
private resolveEnv(template: string): string {
  return template.replace(/\$\{(\w+)\}/g, (_match, name: string) => {
    const value = process.env[name];
    if (!value) throw new ApiKeyMissingError(this.name, name);
    return value;
  });
}
```

Two things this gets right. It fails loudly — an unset `CLOUDFLARE_ACCOUNT_ID`
throws `ApiKeyMissingError` naming the variable, rather than sending a request
to a URL with the literal text `${CLOUDFLARE_ACCOUNT_ID}` in it. And it is
general: any future provider needing a URL-embedded identifier — a region, a
project, a deployment — works with no code change.

It is also the only place in the codebase where a config value is templated.
The mechanism was built for one provider and has one user.

## Errors

Both `stream()` and `embed()` handle a non-2xx the same way:

```ts
const detail = await res.text().catch(() => "");
throw new Error(
  `${this.name}: API request failed (${res.status} ${res.statusText})` +
    (detail ? ` — ${detail.slice(0, 500)}` : ""),
);
```

Including the upstream body — truncated to 500 characters — is the single most
useful debugging decision in the project. Provider errors are specific and
actionable ("model does not exist", "rate limit exceeded, retry in 4.2s",
"insufficient credits") and they arrive intact at the caller instead of being
flattened into a generic 500.

`ApiKeyMissingError` is the other typed error, and its message is a complete
instruction:

```
Missing credentials for "groq": set the GROQ_API_KEY environment variable
(e.g. in your .env file) to use this provider.
```

Both surface as 401 on the non-streaming path, and as an in-stream error object
on the streaming one ([§3.3](../3-api/3.3-streaming.md#errors-mid-stream-are-not-errors)).

## Adding a ninth

Any OpenAI-compatible service works. Append to `providers.yaml`:

```yaml
  together:
    api:
      baseUrl: "https://api.together.xyz/v1"
      model: "meta-llama/Llama-3.3-70B-Instruct-Turbo"
      keyEnv: "TOGETHER_API_KEY"
```

…then `export TOGETHER_API_KEY=...` and restart. No build, no code, no
registration step. Note the model id there contains a slash, so it can only ever
be used as the default — [§3.2](../3-api/3.2-choosing-a-model.md#consequences-of-the-slash)
explains why.

If you edit the bundled `providers.yaml` inside `node_modules`, an upgrade wipes
it. Copy it somewhere and point `PROVIDERS_FILE` at your copy instead.
