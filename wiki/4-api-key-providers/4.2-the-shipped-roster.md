## Reading the table

**`cloudflare` needs two environment variables**, and only one of them is
`keyEnv`. The account id is interpolated into the URL — the mechanism is
[§4.1](./4.1-one-class-many-services.md#the-cloudflare-problem). Set both
`CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` or the provider throws
naming whichever is missing.

**Six of eight have no `embedModel`**, so `/v1/embeddings` against them falls
back to the chat model and fails upstream unless you name an embedding model
explicitly — [§3.4](../3-api/3.4-embeddings-and-auth.md#the-embedmodel-field-exists-because-chat-models-arent-embedding-models).

**`openrouter`'s default model id contains a slash**, so it is reachable only as
the default; `openrouter/<anything>` truncates at the first slash
([§3.2](../3-api/3.2-choosing-a-model.md#consequences-of-the-slash)). The same
is true of Cloudflare's `@cf/...` ids.

## Cost, and the free-tier claim

The project's pitch is pooling free tiers ([§1.1](../1-idea/1.1-what-it-is.md)),
so the split matters:

| | Providers |
|---|---|
| Free tier available | `gemini`, `groq`, `openrouter`, `cerebras`, `mistral`, `cloudflare` |
| Paid only | `openai`, `digitalocean` |

**This is the least durable table in the book.** Free quotas, model
availability and rate limits change on the providers' schedule, not this
repository's, and nothing here is checked against reality. `groq` and `mistral`
required no credit card when the README was written; that could be false by the
time you read it. Treat the split as "what was true when someone last looked"
and the provider's own pricing page as authoritative.

The default model ids age the same way — `gpt-4o-mini`, `llama-3.3-70b-versatile`
and `gemini-2.5-flash` are all pinned in YAML and will eventually be retired
upstream, at which point that provider returns a 404 with a helpful upstream
message ([§4.1](./4.1-one-class-many-services.md#errors)) and the fix is one
line of YAML.

## Getting a key

Links live in one place rather than three, so they can go stale in one place:
[`docs/providers.md`](../../docs/providers.md#api-key-providers), which also has
the exact click-path for Cloudflare's token and DigitalOcean's model access key.
`.env.example` in the package root carries the same list as comments.

The `.env` file is loaded by `import "dotenv/config"` at the top of
`src/cli.ts`, from the **current working directory** — so it is the directory
you run `wspr` in that matters, not where the package is installed.

## What startup tells you

`wspr serve` checks every API provider's `keyEnv` and warns, without failing:

```
Missing API keys — API providers will fail until configured:
  ⚠ openai: set OPENAI_API_KEY=... in .env or export it
  ⚠ cerebras: set CEREBRAS_API_KEY=... in .env or export it

  Copy .env.example to .env and fill in your keys, or set them in your shell.
```

It does not check `CLOUDFLARE_ACCOUNT_ID` — only the declared `keyEnv` — so
`cloudflare` can pass the startup check and still fail on first request. Filed
in [§7](../7-status.md).
